# dv/waves — per-test GTKWave sessions

- `<test>.gtkw` — one session per test (smoke, tx, loop, pm, rxovf, scen, upf),
  generated by `wave_check.py gen` (edit the signal list there, not the .gtkw).
- `wave_dump.sv` — optional second top that dumps `<tb>`, `<tb>.dut`,
  `<tb>.dut.u_ctrl` (depth 1) to VCD; compiled in with `WAVES=1`.
- `wave_check.py check <test> <vcd>` — every session signal must exist in the dump
  and the clocks / reset / FSM state must toggle; if gtkwave + xvfb-run are
  installed it also loads the session headless (`gtkw_count.tcl`) and requires
  every trace to resolve.

`make wave-<test>` runs the test with a dump, checks it, and opens GTKWave when a
display is available. `make waves` = `wave-loop`. `make wave-check-all` checks all
seven sessions without a GUI (this is what CI runs). The Verilator env has its own
FST trace; no `.gtkw` is provided for it.

Notes: in the loopback tests the UCIe-3D Tx bus is wired to the Rx bus, so the
"UCIe-3D Rx" group mirrors the Tx beats (the Rx flit-lock / capture activity shows
up in `rx_idle` and the CDC / Rx health group). The sideband is active only in
short bursts — the byte-serial preset write + its ack at link-up (within the first
~0.1 us, before any frame, so zoom to the start of the dump), and again in `pm` on
every speed / width / preset change.
